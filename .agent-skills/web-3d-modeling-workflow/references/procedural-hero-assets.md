# Procedural hero assets

Use this reference for procedural trees, grass, rocks, gates, roofs, sculptural architecture and other focal assets whose value comes from a reusable construction method. It turns verified ThreeUI techniques into production rules while preserving the distinction between source behavior and required target-project adaptation.

## The five-contract hero model

A reusable hero asset is complete only when these contracts agree:

1. **Shape grammar:** part hierarchy, generation algorithm, semantic parameters, silhouette and level-of-detail behavior.
2. **Surface history:** substrate, coating/mineral/wood structure, wear, cracks, runoff, moss, wetness and their channel outputs.
3. **Physical contract:** anchor, axes, support contacts, complete visual/collision envelopes, closure and winding.
4. **Runtime contract:** seed ownership, shader/version contract, instancing, animation bounds, quality tiers and lifecycle owner.
5. **Evidence contract:** canonical and rotated views, close/grazing material views, topology/support checks, deterministic replay and fixed-state performance.

Do not catalog geometry while leaving its material generator or shader patch as an undocumented side effect.

## Choose a representation class before extraction

Use one explicit class; it determines the physical and camera promises:

| Class | Typical use | Required promise |
| --- | --- | --- |
| `native-three-hero` | torii, books, furniture, standalone architecture | current target runtime, semantic parts, full envelope, support/topology QA |
| `traced-natural-hero` | exposed roots, vines, moss-covered organic forms | landmark/spline evidence, stable frames, closed/tapered shell, seeded surface growth |
| `terrain-scatter` | grass fields, field stones, puddles, debris | shared height/normal/slope service, masks, achieved counts and finite sampling guard |
| `billboard-2.5d` | foreground grass/bough/rock silhouettes, distant mountains | explicit camera/orientation/render-order dependency; no collision or free-orbit claim |
| `canvas-visual` | recursive ink tree, flat growth diagram, UI/background effect | DOM/Canvas lifecycle and accessibility; never cataloged as a 3D model |

Moving a pattern from one class to another is a new implementation. A Canvas branch grammar may inspire a 3D tree, but it does not bring geometry, support, culling or collision evidence with it.

## Semantic parameters, not arbitrary noise knobs

Expose controls that describe the thing being built:

- torii: span, column height, taper, beam rise, corner-lift power, bracket spacing, base/plinth size, lacquer age;
- tree: trunk height/radius, leader dominance, scaffold count, branching depth, length/radius decay, upward bias, canopy radius/density, inward-pull cap, wind strength;
- grass: support mask, blade density, height distribution, lean, clump scale, near/far split, gust amplitudes, interaction radius;
- rock: radius, subdivision, radial displacement amplitude/frequency, vertical compression, burial ratio, clustering and material weathering.

Give every control a reviewed range. Clamp forces that can invert geometry or collapse a distribution. Use separate seeded streams for layout, topology, surface variation and motion phase so a density edit does not unpredictably reshape another subsystem.

## Kage torii: construction grammar

The ThreeUI temple-night renderer builds the red torii as a layered assembly rather than a decorated box. Its useful grammar is:

- two tapered 26-sided columns;
- foot pieces and optional stone support/plinths;
- collars, brackets and small wing details at the column/beam transition;
- a straight lower crossbeam (`nuki`);
- central tablet support (`gakuzuka`) plus a separate gold trim/accent;
- curved upper `shimaki` and `kasagi` beams generated by sweeping a polygon cross-section;
- a separate dark/black cap layer that sharpens the upper silhouette.

For the upper beams, sample a symmetric path using a normalized coordinate `u` and a controllable corner lift:

```text
x = u * halfSpan
y = baseHeight + pow(abs(u), liftPower) * liftRise
```

The source uses 27 path samples. Treat that as a starting point tied to curvature and camera distance, not a universal constant.

### General swept-polygon builder

For every path sample:

1. compute a stable tangent from adjacent path points;
2. choose a reference vector that is not nearly parallel to the tangent;
3. compute a local orthonormal cross-section frame;
4. place the polygon ring in that frame;
5. connect adjacent rings with consistent winding;
6. cap both ends using normals derived from the endpoint path tangents.

The audited source hardcodes cap normals along `±Z` even though its beam path primarily travels along X. The geometry is closed, but the cap lighting normal is not generally correct. A reusable port must derive cap normals from the endpoint tangent or recompute them after a correctly wound cap is constructed.

Ground the assembled group from its lowest support point. The source offsets the group to place column feet at ground level; the Maple Glen adaptation adds two stone box plinths and samples analytic terrain beneath the asset. In a reusable component, return named support contacts and a measured local envelope rather than burying a scene-specific Y offset inside the builder.

## Kage lacquer: surface-history grammar

The lacquer material is valuable because it models substrate, coating and damage in an order that explains the visible result:

1. generate a dark wood substrate with longitudinal structure;
2. apply a mostly opaque vermilion coat;
3. multiply some wood response back through the coat;
4. overlay pigment-scale noise;
5. add long crack paths;
6. create peeled islands that reveal wood, including a raised/rough edge shoulder;
7. add gravity-aligned rain streaks;
8. generate roughness and normal response from the same causal fields.

The source uses an approximately 80% vermilion mix, then blends wood and fBm variation back into it. Preserve the causal layering, not those exact percentages. Retune base color, roughness, environment and exposure together in the target renderer; the source tint compensates for its own grading and is not a portable physical constant.

The wood generator itself models sawn-board evidence rather than generic fBm: cathedral/ring structure, board joints, pores, knots, longitudinal checking and soot/water runoff. The stone generator combines multiple mineral-speckle scales, chisel bruising, pits/fractures and moss derived from low regions in the generated height field. The general rule is:

> Generate wear and biological accumulation from the same construction/height/drainage fields that produced the substrate, then derive color, normal and roughness coherently.

Create generated textures once per parameter set, cache/share materials deliberately, mark color maps as sRGB and keep normal/roughness data linear. Disposal ownership must account for all generated canvases/textures and shared materials.

## Stylized maple tree: structural grammar

The temple source uses seeded recursion:

- low-sided tapered cylinders align their local up axis to a branch direction quaternion;
- child length decays in a bounded random range;
- radius decays separately;
- an upward bias prevents purely radial collapse;
- segments are merged for draw efficiency;
- leaf planes are alpha-tested and animated with a shader patch.

Useful source values include a six-sided segment, depth around four, length decay around `0.62–0.78`, radius decay around `0.66`, alpha test near `0.42`, and bounded upward bias. They are style evidence, not required defaults.

For a hero tree, improve the branch hierarchy:

1. establish a visible central leader;
2. place a small number of major scaffold branches with vertical and azimuthal rhythm;
3. spawn curved secondary twigs from scaffold frames;
4. distribute most leaves along twig paths, not only at branch endpoints;
5. control canopy density independently from branch count;
6. cap inward pull so branches do not fold through the trunk or collapse into a ball.

The source branch cylinders are open-ended and rely on double-sided rendering. That is acceptable only if the asset explicitly declares open thin-tube construction and no end can become visible. A hero asset claiming solid wood must cap segments, join them with correctly constructed junctions, or build a closed branch skin. Do not let `DoubleSide` masquerade as watertightness.

For shader wind, inject a persistent local phase attribute or deterministic world/object-space phase, keep the trunk/branch base stable, and add a stable `customProgramCacheKey`. Check the exact target Three.js shader chunks before patching.

## Traced natural hero: root, vine and moss construction

Sylva demonstrates a stronger route for a focal organic asset than random cylinders:

1. measure landmark points from a source silhouette/alpha or art-directed guide;
2. convert them once into the asset's local coordinate system;
3. interpolate with a centripetal Catmull–Rom curve to reduce overshoot;
4. build cross-section frames with parallel transport;
5. tessellate a closed/capsule-like shell using separate radius profiles for bark and moss cushion;
6. compute actual normals from the tessellated surface;
7. taper terminal rings to a point or construct explicit caps;
8. seed moss blades, ferns or flowers from the same shell attributes.

Parallel transport matters because independently rebuilding a Frenet-like frame can flip or twist near low-curvature and vertical segments. Choose a fallback reference axis when tangent and reference become nearly parallel, then transport the previous normal/binormal with the minimum required rotation. Assert frame continuity by checking adjacent normal/binormal dot products and ring winding.

Drive moss coverage from several causes rather than one noise texture:

- upward/light-facing tendency;
- coarse and fine fBm variation;
- lower-frequency cushion/lump distribution;
- contact/damp darkening and substrate exposure;
- optional art-directed masks from source landmarks.

The moss layer should have geometric thickness where the canonical camera can resolve it. Keep bark and moss radius profiles separate so quality tiers can reduce grass density without collapsing the underlying organic silhouette. Release temporary tessellation/sampling grids once placement attributes have been built; do not retain CPU arrays that no longer own runtime behavior.

Use separate deterministic streams for root geometry and attached vegetation. Ambient pollen/spray may be intentionally non-deterministic, but it must be labeled as an environment system rather than included in an asset reproducibility claim.

## Grass: sampling, blade economy and shading

### Sample the rendered support directly

Sylva's most reusable grass lesson is distribution over an existing tessellated shell:

1. enumerate support cells/triangles already used by the rendered surface;
2. compute a non-negative weight such as `cellArea * supportMask²`;
3. build a cumulative distribution function;
4. pick a seeded target weight and locate the cell by binary search;
5. bilinearly/barycentrically interpolate position, normal and mask data;
6. store per-instance yaw, length, lean, tone and clump attributes.

This avoids expensive rejection sampling, preserves exact agreement with the visible support surface and makes density follow a semantic mask. Keep a guard for zero total weight and report the achieved instance count.

### Use the correct blade topology

The audited Sylva source uses three longitudinal segments: four rungs, two vertices per rung and three quads. That is **six triangles per blade**, not eight. Preserve source facts precisely when estimating budgets.

Japanese Tower uses a different five-rung construction: four quads plus a tip triangle, totaling **nine triangles per blade**. It is a separate recipe, not a contradiction.

### Shader contract

A useful instanced blade record contains:

- root position/offset;
- support normal;
- deterministic random tuple for yaw, length, lean and phase;
- clump/noise value or semantic support weight;
- optional tint/snow/wetness category.

In the vertex shader, construct a local tangent frame around the support normal, apply base lean, then apply wind with a root-preserving profile such as `t²`. Combine slow/global and higher-frequency gust terms. For interaction, map pointer/raycast data into the grass group's local space, push tangentially and press along the normal with influence scaled by blade length.

In the fragment shader, keep root/mid/tip color structure, pile self-shadow and backlit transmission distinct. A tip highlight should remain localized near the last quarter of the blade; adding it after primary lighting prevents the whole surface from washing out.

Use near/far populations with distinct density, height/fog or shader fidelity where measurement proves value. Demo counts such as 190k+60k or 104k are device- and scene-specific, not a budget. Measure triangles, attributes, draw calls, overdraw and frame time on the target device.

Prefer conservative animated bounds computed from maximum blade length, lean, gust and interaction displacement. Use `frustumCulled=false` only when a correct bound is impossible or its calculation is more expensive than the saved work, and document the decision.

## Camera-dependent 2.5D nature layers

Temple-night also generates Canvas cutouts for foreground grass, rocks and maple boughs, then arranges them as a small set of camera-facing layers with explicit render order. This is a powerful fixed-shot composition method:

- create a high-information alpha silhouette with procedural crests/branches/strokes;
- use only a few large planes instead of thousands of 3D elements;
- stagger planes in depth and screen-space height;
- keep render order and depth policy explicit;
- budget fill-rate, texture resolution and transparency overlap.

Catalog these assets as `billboard-2.5d` with camera envelope, allowed yaw/pitch and occlusion order. They do not support free orbit, accurate shadow volume, terrain collision or physical inspection. `frustumCulled=false` and manual `renderOrder` are acceptable only inside that declared shot contract.

## Rocks: hero and background are different systems

### Hero/proximate rocks

Start with a moderate-subdivision icosahedron, displace each vertex radially with seeded multi-scale noise, compress vertically, recompute normals, rotate with a seed and bury a controlled fraction into terrain. Separate macro silhouette noise from small surface breakup so the profile remains art-directable.

For a focal rock, add:

- flatter support face or verified buried base;
- construction-aware fracture planes, chips or erosion bands;
- triplanar/UV-stable material scale;
- convex/mesh collision chosen deliberately;
- close-view silhouette and grazing-normal evidence.

### Background field stones

Japanese Tower demonstrates a separate background strategy: one low-detail icosahedron geometry instanced thousands of times, with analytic terrain height/normal/slope filtering, radial density falloff, seeded transforms and per-instance color. This is suitable for field texture and repetition breakup. It is not a hero rock simply because the aggregate instance count is high.

Use a finite placement guard, report accepted/rejected samples and keep slope, radial density and exclusion masks in typed configuration. Replace direct source `Math.random()` with a seeded stream when repeatability matters.

## Manufactured and architectural hero builders

The Japanese Tower source uses a useful `Bld`-style vocabulary: box, prism, N-sided prism, swept plan, lathe, ring, arc, fan, tube and merged material buckets. This is a shape grammar for multi-part architecture, not merely a convenience API. Preserve semantic assembly IDs before merging; store a build manifest that maps merged draw ranges or source part IDs back to roof, bracket, wall, railing and ornament roles.

For curve/tube construction, prefer parallel-transport frames and a near-parallel reference-axis fallback. Still require an explicit closed/open endpoint policy; a stable frame does not imply a capped solid. Never edit a generated self-contained HTML artifact as the only source. Keep its generator/source file, generation command, input hashes and output revision together.

Bookshelf provides the matching manufactured-product pattern:

- typed per-object records own dimensions, palette and seed;
- rounded page blocks, covers, spine, end papers, ribbons, tabs, seams and foil are separate construction/material layers;
- texture atlases may crop source art with a deterministic Canvas fallback;
- fabric/cloth builds color, height-derived normal and roughness from weave evidence;
- animated pages use named pivots and segmented geometry;
- `userData.construction` exposes board thickness, roundover, spine, stitching and other auditable parameters;
- an oversized transparent hit target is an interaction proxy and must be excluded from visible-geometry/detail claims.

The general rule is to separate visible geometry, construction metadata, animation pivots and interaction proxies. Merging for draw efficiency must not erase audit identity or cause hit geometry to enter collision/visual coverage accidentally.

## Analytic terrain and surface-normal reuse

When procedural vegetation and stones must agree with terrain, make height and normal query functions first-class scene services:

```text
height = terrainHeight(x, z)
normal = normalize([-dH/dx, 1, -dH/dz])
slope = 1 - normal.y
```

Reuse them for mesh construction, grounding, orientation, slope masks, water placement, support audit and collision approximation. Japanese Tower's polar terrain uses logarithmic radial spacing to concentrate vertices near the camera; adopt that only for a constrained viewpoint. A freely orbitable scene needs an allocation strategy tied to world-space error, tiles or LOD instead.

## Validation matrix

| Asset | Required close checks | Required system checks |
| --- | --- | --- |
| torii/gate | beam caps, column taper, bracket contacts, lacquer peel and rain direction | grounded support contacts, full envelope, target grading |
| tree | branch junctions/ends, leaf attachment, leader/scaffold readability | seed replay, canopy bounds, wind cache key, animated culling |
| grass | root contact, blade topology, bend origin, tip alpha | support sampling, achieved count, animated bounds, overdraw/frame time |
| hero rock | silhouette, normals, fracture/material scale | burial/support, collider, seed replay |
| field stones | repetition breakup and slope agreement | instance count/guard, exclusion masks, draw/budget |
| traced root/moss | frame continuity, taper/caps, bark-to-moss offset | seed replay, shell-sampling agreement, vegetation counts, temporary-grid release |
| 2.5D cutout | alpha edge, layer intersections, depth/readability | camera envelope, render order, overdraw, no false collision/free-orbit claim |
| manufactured hero | seams, pivots, material boundaries, interaction proxies | construction metadata, closed parts, typed records, repeated mount/animation cycle |

For every reusable procedural asset, test at least two seeds plus an edge-case configuration at each semantic range limit. Reproduce one seed byte-for-byte or via stable geometry/attribute hashes when serialization permits; otherwise compare deterministic counts, bounds and sampled attributes.
